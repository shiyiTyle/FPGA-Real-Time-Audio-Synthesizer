# FPGA 多音色合成电子琴引擎 —— 双声道输出版

赛题：基于 FPGA 的实时多音色合成电子乐器引擎（本包完成基础要求的音频输出链路）
板卡：Tang Primer 25K（GW5A-25）+ 60033 Dock
DAC ：MAX98357A I2S 功放模块（现用，直推喇叭） / PCM5102（备用，耳机口）

源文件，改稿后重新生成 docx 需用 `.docgen/gen_script.js`。

## 二、接入 Gowin 工程的步骤

1. 把 **15 个** `.v` 文件复制到工程 `src/` 目录，在 Gowin IDE 中添加到工程
   （`dds_voice / demo_seq / i2s_tx / keypad_scan / note_alloc / synth_core /
   video_top / ads1115_drv / bend_ctrl / ttp229_drv / audio_fx /
   porta_ctrl / st7789_drv / viz_scope / viz_spec`）
   — 注意 `ttp229_drv.v` **不能省**：顶层无条件实例化它，缺少会报
   `EX3937: instantiating unknown module 'ttp229_drv'`；`audio_fx.v` 同理
2. **从工程中移除 `press_sensor.v`**（本次已改为 ADS1115 弯音方案，不再使用
   LM393 DO 门控）以及更早的 `wvf_create.v` / `key_play.v`（已废弃）
3. 用本包的 `fpga_project.cst` 替换原工程的约束文件
4. **把 `fpga_project.sdc` 也加入工程**（右键 Add Files，类型选 Timing Constraints）
   —— 不加的话 Gowin 会按 100MHz 优化，实际只跑到 50.7MHz，余量仅 1.4%，
   表现为"有时候上电没声、重烧一次又好了"。加了之后按 20ns 优化，
   布局布线报告里的 Fmax 应达到 55~60MHz。
5. 重新 综合分析 → 布局布线 → 烧录（cst 在 PnR 阶段生效，必须全流程重跑）

## 三、关键修正（为什么必须换约束文件）

原约束把 `sys_clk` 放在 **H11**，但经原理图与官方例程核实：

- **H11 / H10 是核心板按键 S1 / S2**（按下=高电平，未按下悬浮，需内部下拉）
- **板载 50MHz 晶振在 E2 引脚**

原约束会导致 FPGA 完全没有时钟输入。修正版约束：
`sys_clk → E2`，`key_s1 → H11`、`key_s2 → H10`（核心板按键 S1/S2，
按下=高电平，均配 PULL_MODE=DOWN）。

依据：Sipeed 官方 Wiki（Tang Primer 25K）与官方例程约束
（github.com/sipeed/TangPrimer-25K-example 的 pmod_led.cst / litex cst 中
时钟均在 E2）。

## 四、DAC 模块接线

### 方案 A：MAX98357A（现用）

I2S D 类功放，直推 4Ω/8Ω 喇叭（± 两个焊盘），无需 MCLK，自动识别 I2S 格式。

| FPGA 引脚（Dock 排针） | 信号 | MAX98357A | 说明 |
|---|---|---|---|
| G7 | i2s_bclk | BCLK | 3.125 MHz = 64 x fs |
| H5 | i2s_lrclk | LRC | 48.828 kHz = fs |
| H8 | i2s_data | DIN | 串行数据 |
| 5V | 供电 | Vin | 2.5~5.5V |
| GND | 地 | GND | 共地 |
| F5 | i2s_mclk | — | **不接**（该模块无 MCLK 引脚，输出悬空即可） |

配置脚：
- **GAIN**：悬空 = 9dB（默认）。嫌声音小可接 GND（12dB），嫌大可接 5V（6dB）
- **SD**：决定输出哪个声道（三态电平选择）：
  - 悬空（模块默认上拉）= 左声道
  - 直接接 Vin（>1.4V）= 左声道
  - 分压到 0.77~1.4V = **右声道**（如 5V 经 68kΩ/22kΩ 分压 ≈ 1.22V）
  - 分压到 0.16~0.77V = **(左+右)/2 混合**（如 5V 经 100kΩ/15kΩ 分压 ≈ 0.65V）
  - < 0.16V = 关断

注意 MAX98357A 是**单声道**功放，"两路声音"两种做法：
1. **单个模块**：SD 配成 (L+R)/2 混合模式（分压 0.16~0.77V）→ C5/E5 两个拨弦
   都从同一喇叭出，可验证双声部+ADSR
2. **两个模块（真立体声，推荐演示效果）**：两块共用 BCLK/LRC/DIN 三根信号线，
   模块 1 的 SD 悬空（左声道 → 声部 0/2 的 C5），模块 2 的 SD 分压到
   0.77~1.4V（右声道 → 声部 1/3 的 E5），各接一个喇叭

### 方案 B：PCM5102（备用）

| FPGA 引脚 | 信号 | PCM5102 | 说明 |
|---|---|---|---|
| G7 | i2s_bclk | BCK | |
| H5 | i2s_lrclk | LRCK | |
| H8 | i2s_data | DIN | |
| F5 | i2s_mclk | SCK | 可不接（芯片自动用 BCK 锁相） |
| 5V / GND | 供电 | VIN / GND | |

FMT=GND（I2S）、XSMT=VCC（非静音）；背面 H1L~H4L 出厂焊接保持原样。

### 4x4 矩阵键盘（HW-834）接线

键盘 8 根线（丝印 C4 C3 C2 C1 R1 R2 R3 R4）接 USB 口旁排针：

| HW-834 引脚 | FPGA 引脚 | cst 信号 | 说明 |
|---|---|---|---|
| 丝印第1行（S1~S4） | D10 | kbd_row[0] | 行扫描（低有效，空闲高阻） |
| 丝印第2行（S5~S8） | B10 | kbd_row[1] | |
| 丝印第3行（S9~S12） | G10 | kbd_row[2] | |
| 丝印第4行（S13~S16） | C10 | kbd_row[3] | |
| 丝印第1列（S1/S5/S9/S13） | G11 | kbd_col[0] | 内部上拉，按下=低 |
| 丝印第2列（S2/S6/S10/S14） | D11 | kbd_col[1] | |
| 丝印第3列（S3/S7/S11/S15） | B11 | kbd_col[2] | |
| 丝印第4列（S4/S8/S12/S16） | C11 | kbd_col[3] | |

> 行列映射按实测校准。若换接线后某行整体错位，只需对调 cst 里对应
> `kbd_row[x]` 的引脚（代码不用动）。
> 注意：cst 在布局布线阶段生效，改完必须重跑"综合→布局布线→烧录"全流程。

键位 -> 音高 / 音色 / 效果（G 大调，2026-10-28 拓展2 定稿）：

| 键 | 功能 | 键 | 功能 |
|---|---|---|---|
| S1 | G5 哆 | S9  | 原始波形：正弦（f，上电默认） |
| S2 | A5 来 | S10 | 原始波形：窄脉冲（2f） |
| S3 | B5 咪 | S11 | 原始波形：锯齿（f） |
| S4 | C6 发 | S12 | 原始波形：方波（f/2） |
| S5 | D6 唆 | S13 | **乐器：钢琴**（加法合成 3 分量，各自独立衰减） |
| S6 | E6 啦 | S14 | **乐器：长笛**（正弦+二次谐波+颤音+起音气声） |
| S7 | F#6 西 | S15 | **混响 开/关**（按一下切换） |
| S8 | G6 哆（高） | S16 | **延迟回声 开/关**（按一下切换） |

（S13~S16 原"升八度备用音区"已由乐器音色键/效果开关键取代；
  钢琴/长笛按一下全局切换，正在响的音立刻变化，与 S9~S12 互斥按后按生效）

- **音色键按一下全局切换**整个琴的波形，正在响的音立刻变化；上电默认正弦
- 最多 4 键同按 = 4 音复音（音色键/效果键不占声部）；按住延音、松开自然衰减
- 控制到发声延迟 ≈3~9ms（扫描 0.8ms + 消抖 3.2ms + 起音 2ms），满足赛题 ≤10ms；
  效果器为干湿并联，**开启混响/延迟不增加演奏延迟**（拓展3 ≤5ms 论证不受影响）

### 两种乐器音色（拓展2，调音参数在 `dds_voice.v` 头部）

- **钢琴（S13）**：加法合成 f + 2f + 3f 三个分量，各自独立衰减
  （3f ≈0.13s、2f ≈0.31s 先后消失，基频 ≈1.3s 衰减到无声；基波 x5/8、
  2f/3f 相对占比 ≈0.73/0.44，2026-10-31 末听测加亮——正弦/长笛路径
  均未改动）——起音亮、渐暗渐柔，无无限延音、松键阻尼快速收尾。
  按评分规则"加法合成按运算分量统计"，一个钢琴音 = 3 个独立振荡器分量
- **长笛（S14）**：正弦基频 + 15% 二次谐波；70ms 柔起音、满延音；
  **颤音 5.5Hz** 进入延音后 0.4s 内渐入（深度 ±13 音分，模仿演奏者习惯）；
  起音瞬间 ~25ms 气声（LFSR 噪声，吐气 chiff）；134ms 中速释放

### 混响与延迟回声（拓展2，S15/S16 开关）

- **延迟回声（S16）**：0.335s 环形缓冲 + 0.45 反馈，湿声 0.35——单音变
  "回声"效果，连弹形成回声墙
- **混响（S15）**：Schroeder 结构（4 路并联梳状 g=0.805 延迟
  1236/1316/1414/1501 样本，输入衰减 /5 + 2 路串联全通 g=0.7 延迟
  249/378 样本），湿声 0.5（两轮听测：原 0.25 听不出 → 0.375 仍偏弱 →
  2026-10-31 末调至 0.5 + 输入 /5，累计较初版 ≈+10dB）——给声音加
  "房间空间感"，混响尾约 1.5s
- 两者可叠加（都开）；再按一次关闭（缓冲自动写 0 清空，无爆音）；
  效果器全部 FPGA 内部纯逻辑实现，BSRAM 约 25/56 块、DSP 乘法约 26/56 个

### 电位器（滑音）—— **当前 POT_EN = 1，已接单支电位器**

`video_top.v` 的 `POT_EN` 参数：

| 值 | 行为 |
|---|---|
| **1（当前）** | 启用 ADS1115 的 AIN1（滑音量）/ AIN2（颤音深度）。A1 接滑音电位器；A2 的接法决定颤音（见下方" A2 颤音"一节：接 GND=关，接 3V3/分压/第二支电位器=固定或可调颤音） |
| 0 | 滑音/颤音**彻底旁路**：`pinc_glide` 直接连 `pinc_v`，颤音深度恒 0 —— 音色与最初完全一致 |

**为什么拔掉电位器必须改回 0（实际踩过的坑）**：电位器没接时，ADS1115 的
AIN1/AIN2 是**悬空输入**，会读到乱数。固件若照样把这个数当"滑音量/颤音深度"，
后果就是 **每个音都在滑音 + 全程颤音**，听起来完全不像乐器——表现为
"怪声、像消抖没消掉"，但其实是滑音/颤音在乱跑。

**接线（当前实测接法）**：单联 3 脚电位器，中间滑臂 → ADS **A1**，另外两脚
分别 → 3V3 和 GND（哪一脚接 GND 决定顺时针方向：逆时针拧到底时与滑臂电阻
≈0Ω 的那脚接 GND）；**A2 必须用一根线短接 GND**。电位器的 3V3/GND 从
ADS1115 模块的 VCC/GND 焊点或底板任意 3V3/GND 孔取，**绝不能接 5V**
（AINx 超 VDD+0.3V 会烧 ADC，上一块模块就是这么烧的）。金属安装焊片不接。

**滑音范围**：`pot_glide` 由 ADC 码 ×5/4 饱和归一（3.3V 满量程读数 ≈206 →
206×1.25≈257 → 饱和 255），`sh = 6 + glide[7:5]`，时间常数 τ ≈ **1.3ms →
168ms**（95% 到位约 0.5s），**全旋钮行程可用**（原 >>7 直映射下 sh 在
旋钮 1/3 处就封顶、上半圈无控制感，2026-10-31 修正）；旋到最小基本等于
不滑音。方向反了就对调电位器两端两根线。

**排查接线（屏上电平条，2026-10-31 新增）**：按住核心板 **S1**，状态条
变为三通道 ADC 电平表——格 0~4 = A0（FSR，绿）、格 6~10 = A1 滑音（青）、
格 11~15 = A2 颤音（黄）。转哪个旋钮、哪组条就该动；悬空的通道会随机
闪烁。若"转滑音旋钮动的是青条、转颤音旋钮青条也动"，说明两支电位器的
滑臂线接错通道，把接 A1/A2 的两根线对调即可；若某组条一直闪烁说明该
通道悬空。松手即恢复正常状态条，不影响演奏。

**A2 颤音（`pot_vib = ADC码>>7`，进 `dds_voice` 的 `vib_man`，**全音色生效**）**
⚠️ 若改用 A2，必须**先拆掉 A2 到 GND 的那根短接线**。**2026-10-31 末定稿
改为振幅颤音（tremolo）**：音高不变，音量随 5.5Hz LFO 像揉弦一样"呼吸"
起伏——旋钮拧满 **±25% 音量摆动**（比音高颤音明显得多、且不跑调），拧小
平滑减弱到 0（旋钮最小 = 与直通完全一致）。长笛内置音高颤音 ±13.3 音分
保持不变。实现：每声部颤音乘法器两拍轮转（一拍长笛音高、一拍振幅
wave_e×LFO 系数），零新增 DSP。三种接法任选：

| 接法 | 效果 | 需要的器件 |
|---|---|---|
| A2 直接接 3V3（把原来接 GND 那根挪过去） | 固定满档 ±25% 音量呼吸 | 无 |
| A2 经 10k/22k 分压到地（3V3—10k—A2—22k—GND） | 固定 ≈±14% 音量呼吸 | 2 只电阻 |
| 第二支电位器（滑臂→A2，两端→3V3/GND） | 0 ~ ±25% 可调 | 第二支 3 脚电位器 |

本轮 PnR（2026-10-31 末）：Fmax **58.321MHz**、Setup/Hold 违例 0、逻辑
13,497（59%）、DSP 28/28（无软乘法）；bitstream 归档
`tremfix_20261031/fpga_project_tremfix.fs`；回归 `sim_tb/tb_trem.v`（摆动比
1.62 实测 PASS、旋钮归零直通 PASS）+ tb_flute + tb_piano 全 PASS。

三种接法**都不用重新烧录**：`POT_EN=1` 时 ADS 一直在轮询 AIN2（A0→A1→A0→A2，
每 ≈11.2ms 更新一次），A2 电压一变 `vib_man` 立刻跟着变。注意 `vib_man` 是
全音色生效——**钢琴音色也会带上颤音**；只想给长笛/正弦加，就得在 `dds_voice`
里按 `timbre` 门控 `vib_man`。

> **⚠️ 2026-10-31 根因修正**：之前"滑音关不掉/两个旋钮都像颤音"的结论是
> 硬件接线问题——**不对，真凶是固件**：ADS1115 驱动用连续转换模式，
> 切通道后只等 1.2ms 就读数，但新通道出数最坏要 ≈2.33ms，A1/A2 约 3/4 的
> 读数其实是 A0（FSR）的旧值（FSR 松开≈3.25V → 滑音恒最大、颤音恒满档，
> 每音都滑、全音色抖、旋钮失灵，而且按 FSR 会带动"颤音"）。已改为单次转换
> 模式（详见六之四），烧录最新 `adsfix_20261031/fpga_project_adsfix.fs` 后
> 电位器才会真正生效。

## 五、预期现象（默认 PLAY_MODE=0 矩阵键盘，CH_MODE=0 单声道镜像）

- **按 S1~S8**：G 大调哆来咪发唆啦西多（G5~G6）
- **按 S9/S10/S11/S12**：切换原始波形音色——正弦 / 高八度窄脉冲 / 锯齿 /
  低八度方波，按住琴键的同时按音色键可立即听到变化
- **按 S13**：切到**钢琴**音色（加法合成，起音亮、自然衰减到无声）
- **按 S14**：切到**长笛**音色（柔起音，0.4s 后颤音渐入）
- **按 S15**：混响开/关；**按 S16**：延迟回声开/关（两个效果可叠加）
- **多键同按**：和弦（最多 4 音），单喇叭也能全部听到（CH_MODE=0 已把
  所有声部镜像到左右声道）
- **按住琴键 + 推压 FSR**：音高连续上滑（最多 +2 半音），松开 FSR 滑回
  本音——压力->音高的第二演奏维度；和弦同推同滑
- **弹不同的音 + 转滑音电位器**：音符之间**滑音过渡**（portamento），旋钮
  逆时针到底≈不滑（1.3ms），顺时针到底≈0.5s 滑到下一个音（全行程可用，
  2026-10-31 起）；与 FSR 弯音互不干扰（先滑音后弯音）
- **松开**：约 0.25s 余音淡出

### FSR 压力弯音维度（当前生效：压力控制音高）

- 信号链：FSR402 -> LM393 模块分压位 **AO** -> ADS1115 **A0**；
  ADS1115 **VCC/GND -> 底板 2x6 排针块的 3V3/GND**（该块无 5V，物理杜绝
  错接 5V——上一块 ADS1115 即死于供电回路接错发烫烧毁）、
  **SCL -> A11、SDA -> E11**；LM393 的 DO->K5 保留接线但已退出固件
- 实测方向：**松开 AO≈3.25V（码值≈26000）、按压越重 AO 越低（压死≈0V）**，
  固件按此方向映射；通电前先蜂鸣档逐根核线
- 行为：**琴键功能完全不变**（选音/触发/音色/包络照旧）；按住琴键时推压
  FSR，音高连续升高，满压力升 `BEND_SEMI` 个半音，松开回本音；和弦各音
  同比例弯音，相对音程不变
- 参数（`video_top.v` 里 `u_bend`）：`BEND_SEMI` 0~12 半音（默认 2，0=关闭）、
  `REL_CODE`（松开读数基准，实测 26000）、`SLEW_STEP`（平滑度，全程≈3.5ms）
- 可靠性：ADS 860SPS，压力->音高更新 ≈2ms；20ms 无数据看门狗自动回本音
  （断线不飙音）；若实测"越用力音越低"说明 AO 方向接反，检查 A0 接线
- 回退点：`backup_press_gate_20261027\`（本次改动前，LM393 触发版）、
  `backup_stable_20261025\`（纯键盘版）、`ads_version_20261025\`（音量版）

## 六、控制→发声总延迟（拓展3 指标 ≤5ms：本设计最坏 ≈4.08ms，抖动 ≤0.4ms）

逐级延迟预算（50MHz 时钟，fs = 48828Hz）：

| 环节 | 最坏耗时 | 依据 |
|---|---|---|
| 矩阵扫描定位按键 | 0.40 ms | 每行 ROW_SETTLE=5000 clk（0.1ms）× 4 行/轮 |
| 消抖确认 | 3.20 ms | 连续 8 次采样确认 × 每键采样率 2.5kHz |
| 声部分配 + 合成流水线 | < 0.2 µs | note_alloc 1 个 clk + dds_voice 5 级流水 |
| I2S 发送缓冲 | ≤ 41 µs | 至多 2 个采样帧（1 帧 = 1/fs = 20.5µs） |
| MAX98357A 内部插值滤波 | ≈ 0.44 ms | 数据手册群延迟 ≈ 21 个采样周期 |
| **合计** | **≈ 4.08 ms** | **≤5ms，余量 1.23 倍** |

**消抖窗口必须是 3.2ms（踩过两次坑）**：
- 第一次把 DBNC 降到 8@5kHz（1.6ms）→ 触点抖动漏滤、按键重复触发、声音变怪；
- 第二次把行建立时间压到 0.05ms/行（5kHz 采样）配合 3.2ms 窗口，长引线下仍不放心；
- 现在的组合：**0.1ms/行（10 倍 RC 时间常数）+ 2.5kHz 采样 + 8 次确认 = 3.2ms**，
  和最初完全相同的积分窗口，只是把行建立时间留足了余量。
  **3.2ms 是这套 HW-834 键盘的实测下限，不要再往下压。**

**为什么是"确定性无抖动"**：
- 上表各项全部由计数器常数决定（代码可查、可算），不存在软件调度、
  缓冲欠载、操作系统抢占等不可预测因素；
- 唯一的抖动源是"物理按下时刻落在哪个扫描相位"——每轮 0.2ms，
  即抖动峰峰值 ≤0.2ms（旧版 ROW_SETTLE=10000 时为 0.8ms）；
- 合成为逐样本实时运算（非块处理），**无音频块缓冲延迟**；
- 效果器（混响/延迟）与 LCD 全部是旁路/独立通路，**不进入发声链路**，
  开效果、刷屏都不改变延迟。

**实测方法（答辩演示）**：
- 示波器 CH1 → **G5（dbg_lat）**：任一音符声部触发时为高（上升沿=引擎开始渲染）
- 示波器 CH2 → 喇叭/AMP+ 输出：音频起振
- 按下琴键，读 CH1 上升沿到 CH2 起振的 Δt ≈ **0.5ms**（流水+I2S+DAC 实测段）
- 物理按键→CH1 的最坏 1.8ms 由扫描/消抖计数器常数解析保证
- 总延迟 = 1.8ms（解析）+ 0.5ms（实测）≈ **2.3ms ≤ 5ms** ✓

## 六之二、实时视听反馈（拓展3，ST7789 240×240 IPS）

屏幕布局（240×240 竖屏）：

| 区域 | 内容 |
|---|---|
| y 0~111 | **示波器波形**：240 列，每列取 4 个样本的 min/max 画竖线 |
| y 112~215 | **16 根实时频谱柱**：Goertzel 递推，203Hz~10.1kHz 对数分布，柱底对齐下沿 |
| y 216~239 | **16 格演奏指引/状态条**：格 0~7 音符键（按下即亮，绿）；格 8~13 当前音色（青）；格 14 混响、格 15 延迟（黄） |

技术要点（答辩可讲）：
- **触发捕获**：波形上穿零（prev<0 且 now≥0）开始收 960 个样本，静音 25ms
  超时则自由运行 —— 图像稳定不滚动，和真示波器一个原理；
- **每列一个点**：960 样本按 1/4 抽取成 240 列，每列画 3 像素短竖线连成波形。
  G6(1568Hz) 在 960 样本里约 30 个周期、每周期约 8 个点，形状清楚。
  （曾用"每列 4 样本 min/max 包络"，实测吃 2,786 逻辑，把总量推到 94% 布线失败，
  故降级为单点方案 —— 详见下面的资源说明）
- **擦旧点（关键）**：每列记住上一帧点位，只擦旧点、画新点，点位没变就跳过。
  早期版本只画不擦，绿色会一帧帧累积把屏幕涂满（已实测复现并修复，
  回归测试 `sim_tb/tb_viz.v` 用虚拟帧缓冲检查"远离中心线"的绿像素数：
  静音 0 → 大音量 720 → 回静音必须回到 0）；
- **自动量程**：按本帧峰值选左移位数（0~7 级），使峰值落在 12800~25600；
- **频谱**：Goertzel 是"只看一个频点"的 DFT，每样本只需 1 次乘加
  s[n]=x[n]+C·s[n-1]-s[n-2]；16 个频点共用 1 个乘法器、每样本推进 16 拍
  （占采样周期的 1.6%），窗口 960 样本（19.7ms）结束时算幅值；
  累加器必须 28 位（N×A/2 在满幅时约 1.57e7，24 位会溢出）；
- **并行架构**：采集、渲染、SPI 发送三级流水，整帧约 27ms（≈37fps），
  且**完全独立于音频通路**——屏不刷新也不影响发声。

### 资源预算（GW5A-25：23040 逻辑单元 / 56 BSRAM / **28 DSP**）

用 Gowin 命令行综合实测（`GowinSynthesis.exe -i ... -top video_top -p GW5A-25B`）：

| 部分 | 逻辑占用 | 说明 |
|---|---|---|
| 全设计（本轮 DSP 优化后） | **11,333（50%）** | 原为 18,856（82%）|
| DSP | **22 / 28** | 原为 28/28 打满并溢出到软乘法 |
| 寄存器 | 3,700（16%） | |
| BSRAM | 28 / 56（50%） | 延迟线 + 混响 + 波形缓冲 |

**关键教训（这是"怪声/没声"的真正根因）**：
GW5A-25 只有 **28 个 DSP 乘法器**（不是 56，56 是 BSRAM）。原设计需要约 39 个
乘法器，超出的 11 个被综合器放进 LUT/ALU 做"软乘法"——软乘法一条就要
100~200 个逻辑单元且延迟很长。结果：逻辑冲到 82%、布局布线报告
**Fmax 41.5MHz < 50MHz、183 个端点违例、TNS -493ns**。这种"擦边"不会让芯片
罢工，而是让寄存器**偶尔采错一位**：pinc 错位 → 音高发毛；gate 错位 →
同一音符重复触发进不同声部 → 听起来"几个声音叠在一起、不干脆"。

**本轮 DSP 优化（音色算法与参数一字未改）**：
| 优化 | 省 DSP |
|---|---|
| `bend_ctrl` 4 声部相乘改为单乘法器 4 拍分时 | −3 |
| `audio_fx` 全部 10 个乘法合并为 1 个 + 14 拍序列器 | −9 |
| `dds_voice` 力度乘法移到混音级（4 声部共享 1 个） | −3 |
| `dds_voice` 长笛二次谐波系数（常数 4915）改移位加 | −1 |
| `dds_voice` 颤音乘法 pinc 截 27 位（27x12 只占 1 个 DSP） | −1 |
| `dds_voice` 钢琴 2f/3f + 长笛气声三个乘法共用 1 个 | −2 |

效果：**逻辑 18,856 → 11,333（82% → 50%）**，DSP 28/28 打满 → 22/28，
布线拥塞大幅下降，为时序留出余量。

**验证方式（重要，可复现）**：改动前先用仿真把当前版本的输出存成"金标准"，
改完后逐样本对比：
- 正弦段、钢琴段：**逐位完全一致（0 个差异样本）**
- 长笛段：包络 RMS 误差 0.82%（波形逐样本不同是因为颤音相位累积差
  1~2 个采样，听感无差异）
- 回声/混响尾能量：2001 vs 2002、2651 vs 2741（同一量级）
- 可视化擦除、频谱三频点、整链 15 帧：全部 PASS

**注**：`audio_fx` 旧版的"混响"其实有 bug——梳状滤波器的反馈读的是**上一个
槽位**而不是 L 拍之前的内容，等于一个泄漏积分器，不是真混响。本轮重写后
是标准 Schroeder 结构（真 L 拍反馈），共振储能更强，因此把梳状输入衰减
到 /8、湿声压到 0.25 倍来留余量（实测已不饱和）。**听感上会比旧版"更像房间"**。

**踩过的坑（重要）**：可视化第一版（min/max 包络 + 每列 3 任务擦除 + 240 项
寄存器数组存上一帧端点）把总量推到 **95%**，Gowin 布局布线直接
`PR0004: 3167 unrouted nets`（布不通）。修法两条：
1. 把"上一帧端点"从 240 项寄存器数组改成 **BSRAM 双缓冲**（省 ~3,500 寄存器，
   且 240:1 选择器消失）；
2. 波形从 min/max 包络降级为"每列一个点"（省 ~1,400 逻辑）。
另外：**寄存器数组千万不要写复位 for 循环**，否则综合器无法推断成
分布式 RAM，会退化成 FF + 大选择器。

若日后还要加功能，下一步该做的是**声部时序复用**（4 个声部共用一套振荡器
逻辑、每样本分 4 拍计算），可把 `synth_core` 从 10,579 压到约 3,500，
腾出 30% 空间；代价是重写 `dds_voice` 的查表结构与流水线。

刷新率/带宽：SPI 12.5MHz（50MHz/4）。全屏填充 73.7ms（仅上电一次）；
单列 = 7.0µs 窗口命令 + n×1.28µs。想更快可把 `st7789_drv` 的 `SPI_DIV`
改成 2（25MHz，ST7789 写周期下限 66ns≈15MHz，属超频，需视连线质量而定）。

调试入口：
- `st7789_drv` 的 `Y_OFF`（默认 0=竖屏无偏移；画面整体上下错位/错行改成 80）
- `viz_scope` 的 `TRIG_TMO`（触发超时，默认 1200 样本 ≈25ms）
- `viz_scope` 的量程阈值（`P_GAIN` 里的 12800/6400/...）与 `C_SPEC` 频谱柱颜色
- `viz_spec` 的 `BAR_MAX`（柱高上限 104）和 `coef` 表（频点分布）

### 布局布线时序记录（2026-10-30，重要）

综合资源降下来不等于能烧板——**必须看 PnR 报告的 Actual Fmax 和违例数**。
2026-10-30 第一次把整套设计（4 声部 + 双效果器 + 频谱）做完 PnR 时：

| 指标 | 修复前（16:43 烧板版） | 修复后 |
|---|---|---|
| Actual Fmax | **45.529 MHz**（约束 50） | **57.024 MHz** |
| Setup 违例端点 | **124**（TNS −126.7 ns） | **0**（TNS 0） |
| 逻辑 / 寄存器 | 11,424（50%）/ 3,700 | 11,725（51%）/ 3,891 |

修复前最差三条路径（全是长组合链，与音色算法无关）：

1. `dds_voice` 输出 → 4 声部求和 → 力度乘 → 限幅 → `audio_fx` → 送屏，
   22 ns（`u_viz` 的 BSRAM 数据口）；
2. `viz_spec` 的 `bi` → 累加器 16 选 1 → 平方 → 位长 → 柱高 → 写回，21.8 ns；
3. `dds_voice` 插值乘法 → 插值加 → 限幅 → 音色 mux → 包络乘法 DSP 输入，

- `synth_core` 混音/力度/限幅改两级 tick 流水（音频晚 2 个采样 ≈41 µs）；
- `viz_scope` 的 `audio`/`audio_tick` 入口先打一拍；
- `viz_spec` 幅值计算由 2 拍改 4 拍流水；
- `dds_voice` 插值结果加 `interp_r`，`wave_i` 后加 `wave_i2`
  （防止寄存器被吸收进 DSP 输入，否则音色 mux 并进长链）。

回归：正弦/钢琴段与金标准逐位一致（整体晚 2 个采样），长笛/回声/滑音
块 RMS 误差 ≤0.03%；`tb_spec`、`tb_viz` 全 PASS。改完的 bitstream：
`timing_fix_20261030/fpga_project_timingfix.fs`。

## 六之四、ADS1115 连续模式读数竞态（2026-10-31 晚定位——"电位器失灵"的真正根因）

### 症状

用户听测："两个电位器都像颤音、滑音没有控制点、正弦波也一直滑音、屏上
波形一直抖、怀疑一母分三母分压线"。按 FSR 反而会带动"颤音"。

### 根因（`ads1115_drv.v` 的时序竞态，与接线无关）

驱动每切换一个通道：写配置（新 MUX）→ 等 `RD_WAIT`=1.2ms → 读转换结果。
但 ADS1115 工作在**连续转换模式**时，写入新 MUX 并不打断正在进行的转换：
芯片内部按 1/860s ≈1.16ms 的固定节拍自由转换，新通道的转换要等当前
转换结束才开始，**最坏要 ≈2.33ms 才能出新结果**。1.2ms 时读数，约 3/4 的
概率读到**上一个通道（A0/FSR）的旧值**。

后果链：FSR 松开时 A0≈26000 → `pot_glide`≈255（滑音恒最大，**每弹一个音
都滑 ≈0.5s**）、`pot_vib`≈203（颤音恒满档 ≈±21 音分，**所有音色包括正弦
全程抖**）→ 两个电位器怎么转都"没效果"、像在控制颤音；压 FSR 时 A0 变小
，"颤音深度"跟着变。而 A0 自己读到的永远是 A0（同通道的旧值），所以 FSR
弯音一直正常——完全对得上"FSR 一直好、电位器全失灵"的现象。

### 修复

- 配置字 MODE 位 0→1（**单次转换**）：`CFG_HI0/1/2` 0xC2/D2/E2 → 0xC3/D3/E3。
  单次模式下每次写配置（OS=1）**精确触发一次转换**，1.16ms 后结果寄存器
  里一定是新通道的结果，读到的再不会是旧值。
- `RD_WAIT` 60000→80000（1.2→1.6ms）：覆盖 1.16ms 转换时间 + ADS 内部时钟
  约 10% 容差余量。
- 代价：轮询周期略变长——FSR 更新 ≈4.6→5.6ms、电位器 ≈9.2→11.2ms，
  bend_ctrl 的 20ms 看门狗不受影响。

### 验证与结果

- PnR：Setup/Hold 违例 **0**、Fmax **57.106 MHz**、逻辑 12,593（55%）、
  DSP 28/28（本次只改配置字节与等待常数，零新增资源）。
- bitstream 归档 `adsfix_20261031/fpga_project_adsfix.fs`。
- 仿真无法覆盖（无 ADS1115 行为模型），此修复依据数据手册时序推算；
  **上板判据**：烧录后按住 S1 看电平条——转滑音旋钮只有青组动、转颤音
  旋钮只有黄组动、按 FSR 只有绿组动（修复前 A1/A2 两组会跟着 A0 走）。
  若仍是三组联动或某组乱闪，再查接线（滑臂线、分压器两端、共地）。

### 关于"一母分三母"分压线

分压线本身不是这个故障的原因：**3V3 并联供两个电位器 + ADS 模块 VCC 在
电气上是没问题的**（电位器每个只有 0.33mA）。两条真正的红线：① 分压线的
任何一根分支**不许接进 ADC 输入端**（A0/A1/A2 只能接滑臂那单独一根线）；
② 分压线接触不良会让 ADS 的 VCC 波动、所有读数一起抖——上电后量 ADS
模块 VCC-GND 应为稳定 3.3V，拧旋钮时不变。嫌杜邦分压线不牢就把两根
电位器的顶端直接焊到 ADS 模块 VCC 焊点（同一焊点并两根线），比 Y 分线器
可靠。
